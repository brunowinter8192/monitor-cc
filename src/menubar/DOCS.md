# src/menubar/

## Role

Standalone macOS status-bar (menubar) application that shows all currently-running Claude Code sessions on this Mac with their working/idle status and background-task badge. Independent of the tmux TUI — launched via `workflow.py --mode menubar` or launchd. macOS only (rumps/AppKit).

## Public Interface

`from src.menubar import run` — `run()` is the sole entry point. Called by `workflow.py --mode menubar`.

## Flow

1. `run()` (system.py) → sets `LSUIElement=1` env → acquires singleton lock → instantiates `CCMenuBarApp` → `app.run()` starts AppKit runloop.
2. `CCMenuBarApp._tick()` (app.py) fires every 1.5s → `list_alive_sessions()` → `_scan_bg_sleep_timers(cwd_to_project)` → `focus.tick()` (auto-focus debounce only — auto-abort removed 2026-08, see `bg_timer.py`/`focus_controller.py` entries) → if panel closed: blink on status change; `panel.rebuild()` only on session-set change; if panel open: on None↔Some transition or session-set change call `panel.rebuild()` (adds/removes abort button, grows panel), otherwise `panel.update_inplace()` (updates NSButton attributed titles only, no resize).
3. `list_alive_sessions()` (discover.py) → refreshes CC-process cache, tmux state, and the bg-task open-handle cache (proc_cache.py, one global `lsof +D /tmp/claude-<uid>` scan per `_PROC_REFRESH_INTERVAL`) → refreshes Ghostty TTY-to-UUID mapping (ghostty.py) → scans `~/.claude/projects/*/` → determines working/idle status per session type → `_has_active_bg()` (proc_cache.py) reports a session's background task as in-progress iff a process currently holds an open write handle on one of its `*.output` files under `/tmp/claude-<uid>/` — not file size (a writing task goes non-zero within seconds while still running for minutes; only an open handle is a reliable liveness signal).
4. Click on a main session → `_focus_session(cwd)` (system.py) → looks up Ghostty terminal UUID (ghostty.py) → `focus terminal id "<UUID>"` (Path A) or cwd-match fallback (Path B). Same path triggered by Cmd+1..9 when panel is open (see hotkey_controller.py + app.py lifecycle).
5. Click on a main session's monitor column → `_open_or_focus_monitor(cwd)` (system.py) → `tmux_launcher.py:check_session_exists(generate_session_name(cwd))` → running: `tmux_launcher.py:kill_session(session_name)` first; either way, always opens a NEW Ghostty window running `cd <MONITOR_CC_ROOT> && python3 workflow.py --project <cwd>` in the foreground (2026-09-04 fix: a stale session whose Ghostty window was already closed used to make the click a silent no-op via `_focus_worker`; now every click ends in a fresh monitor).

## Modules

### panel.py (318 LOC)

**Purpose:** NSPanel construction, NSView/NSTextField/NSButton subclasses for cursor tracking, all UI factory helpers, and pure computation helpers. Render functions (`rebuild`, `update_inplace`, `_resize_panel`) and re-entry guard moved to `panel_manager.py` (Step 4/6). Footer has two buttons: Kill (left) + Restart (right). Main session rows show the real macOS Mission Control desktop number as slot prefix `[N]` (`_GRID_COL0_W=40`, now in `panel_grid.py`), driven by `SessionInfo.desktop_no`; a conflict (2+ mains on the same desktop) shows `[!N]` in red; detection-failed mains (`desktop_no=None`) show no prefix. Workers carry no prefix. `_project_desktop_no(sessions, project_name)` returns `min(desktop_no)` across a project's mains (None if all-None) — used by `panel_manager.py` for the desktop-ordered sort key. Per-project abort buttons (Option B) embedded inline in separator rows — `_make_separator_view` returns `(NSView, Optional[NSButton])`. **Monitor column (2026-09):** 6th grid column, main rows only — `_GRID_COL5_W=40` for the "mon" launch/focus button (`panel_manager.py`, action `openMonitor:`). `PANEL_WIDTH` raised 380→422 (`_GRID_COL5_W + _GRID_COL_SPC`) so the flexible name column keeps its pre-existing effective width unchanged — deliberately NOT added to the badge column (col 4), which already carries bg-task-remaining state and is absent on most rows; overloading it would mix two unrelated meanings and hide the launch control whenever a badge renders. Defines `_KeyablePanel(NSPanel)` — overrides `canBecomeKeyWindow` to return True so both panels can receive keyboard events despite `NSWindowStyleMaskNonactivatingPanel`; imported by `rag_controller.py`. Also overrides `performKeyEquivalent_` to route Cmd+{V,C,X,A,Z} and Shift+Cmd+Z to the first responder. Pure UI concern — no rumps, no ctypes, no subprocess, no direct `app` instance access.
**(2026-09, menubar milestone B) constant-cluster split:** `panel.py` carried 3 constant clusters (`ICON_*`, `_GRID_*`, `PANEL_*`) in one file (threshold: 2+ clusters/file) and `_make_nspanel` was 57 LOC (threshold: 50) — split by cluster into 3 new sibling modules (byte-identity harness unaffected — `dev/menubar/panel_manager_byte_identity.py` covers the consuming side): `bar_icons.py` (`ICON_*`, used only by `app.py`), `panel_grid.py` (`_GRID_*`, used only by `panel_manager.py`), `panel_dims.py` (`PANEL_*`, used by `panel.py` itself plus `app.py`/`app_settings.py`/`model_panel_ui.py`/`rag_controller.py`). `panel.py` imports `PANEL_*` back from `panel_dims.py` for its own `_make_nspanel`/`_reposition_panel` use; it never used `ICON_*`/`_GRID_*` internally, so no re-import needed for those. `_make_nspanel` (57→40 LOC) split into `_make_panel_footer(pw)` and `_make_panel_top_bar(pw)` helpers.
**Reads:** function parameters only (sessions, bg_by_project, panel_width passed from callers). No direct `app` instance state accessed.
**Writes:** NSPanel frame (via `_reposition_panel`); creates NSView/NSButton/NSTextField UI objects returned to callers.
**Key signatures:** `_make_nspanel()`, `_make_panel_footer(pw)`, `_make_panel_top_bar(pw)`, `_reposition_panel(panel, nsstatusitem)`, `_compute_required_height(sorted_sessions)`, `_make_separator_view(project_name, panel_width, proj_min_remaining)`.

### proc_cache.py (165 LOC, orchestrator-signal reader removed 2026-08; discovery-thread lock added 2026-08 M3)

**Purpose:** Process and state caches — CC process pid→(tty,cwd) mapping, tmux session state, bg-task open-handle snapshot, proxy log mtime lookup, hook state reader. Two TTL classes: `_PROC_REFRESH_INTERVAL` = 10s for the expensive `ps -A` / `lsof` caches (also governs `_refresh_bg_task_cache`); `_HOOK_REFRESH_INTERVAL` = 1s for the cheap hooks.json read (must be < POLL_INTERVAL=1.5s so each menubar tick gets a fresh snapshot while intra-tick consumers still see consistency). `_TMUX_REFRESH_INTERVAL` = 3s for `tmux list-sessions`. Owns `_TASKS_BASE` and `_has_active_bg()`. `_has_active_bg(encoded_dir, session_id)` is handle-based, not size-based: True iff a process currently holds an open write handle on a `*.output` file in that session's tasks dir. File size is not a reliable liveness signal — a background task writing progress goes non-zero within seconds of starting while still running for minutes, and a stale 0-byte file left by a crashed/no-output task never gets cleaned up. `_refresh_bg_task_cache(now)` does ONE global `lsof +D _TASKS_BASE -Fn` scan per `_PROC_REFRESH_INTERVAL` covering every session's tasks dir at once (measured ~100ms regardless of session count — same cost as one per-session call would have been, but paid once per refresh window instead of once per session per tick); populates `_bg_task_open_paths` (set of currently-open `*.output` real paths). `_has_active_bg` then does an O(1) string-prefix check against that snapshot — no subprocess call on the query path. Fail-open: an `lsof` error leaves the previous snapshot in place (never escalates a stale reading to "always busy"). `_TASKS_BASE_REAL` is the symlink-resolved form of `_TASKS_BASE` (`/tmp` → `/private/tmp` on macOS) — required because `lsof` reports resolved paths. `_tmux_window_activity(session)` returns unix timestamp of last pane byte-write via `tmux display-message #{window_activity}`; used by `discover.py` for worker stale-demote (replaces JSONL mtime check).
**2026-08 removal:** `_read_orchestrator_signals`, `_orchestrator_signal_cache`, `_orchestrator_signal_last_read`, and the exported `ORCHESTRATOR_SIGNAL_BUFFER_SECS` constant were removed — `focus_controller.py`'s auto-abort logic was their sole reader, and auto-abort itself was removed the same milestone (`worker-cli wait` is self-terminating, no push-abort needed). `paths.py:ORCHESTRATOR_SIGNALS_FILE` and the file it points at are UNTOUCHED — `worker-cli send` (iterative-dev plugin, a separate repo, out of this milestone's scope) still writes to it before every tmux send-keys; the file is now an orphaned write-only artifact from the menubar's side. **2026-08 M3 — `_cc_proc_cache_lock` (see `process-docs/hotkey_latency/`):** discovery moved to a background thread (`discovery_worker.py`), which is now the sole caller of `_refresh_cc_proc_cache`. That leaves ONE genuine cross-thread access: `ghostty.py:_tty_for_cwd`, called from `system.py:_focus_session` on the main thread (click/hotkey), used to iterate `_cc_proc_cache.items()` directly — with a second thread now mutating the same dict, that iteration could raise `RuntimeError: dictionary changed size during iteration` (confirmed via a real concurrent stress test: the unprotected pattern threw 213 errors in a 2s/4-reader stress run; the fixed pattern threw 0 in an equivalent 3s run). ## Title-Marker Mapping (tty → Ghostty terminal UUID)

**Problem:** Ghostty's AppleScript `working directory` property reflects the PTY's initial cwd, not the shell's current cwd. `focus (first terminal whose working directory is "...")` fails for sessions where the shell ran `cd X && python3 workflow.py --project Y`. Ghostty does NOT expose `tty` or `pid` via AppleScript.

**Solution:** OSC 2 title-marker bootstrap. Each Ghostty tab has a direct child process (login shell) with a known TTY device (`/dev/ttys<NNN>`). Writing `\033]2;<marker>\007` to that device sets the Ghostty tab's `name` property. An AppleScript query immediately after returns `id|||name` pairs → marker appears in `name` → we learn the UUID for that TTY.

**Probe flow** (`_refresh_ghostty_tty_to_id` in `ghostty.py`):

1. `ps -A -o pid=,command=` parsed for `Ghostty.app/Contents/MacOS` → Ghostty PID.
2. `ps -A -o pid=,ppid=,tty=` filtered by ppid = Ghostty PID → all current TTYs (`all_ttys`).
3. **Stale cleanup**: remove `_ghostty_tty_to_id` entries whose TTY is no longer in `all_ttys` (closed tabs).
4. **Incremental filter**: `new_ttys = [t for t in all_ttys if t not in _ghostty_tty_to_id]`. If empty → return immediately, **no title flash, no sleep**.
5. Write `\033]2;__GHT_<8-hex-random>\007` to each `/dev/<new_tty>`.
6. `time.sleep(0.12)` — 120ms for Ghostty to process the OSC 2 sequence.
7. `osascript` → all terminals `id|||name` pairs (newline-separated).
8. **Cleanup**: write `\033]2;\007` (empty string) to each probed TTY → shell restores its default title.
9. Match markers to IDs → merge into `_ghostty_tty_to_id`.
10. Update `_ghostty_tty_last_refresh = now` **only if probe ran** (step 4 found new TTYs).

## Gotchas

- **Session status detection** (Workers + Mains): Priority-1/2/3 fallback chain with threshold values — see `process-docs/menubar_session_status/menubar_session_status.md` for the full current-state chain.
- **Singleton enforcement via fcntl lock** (`system.py`): `run()` calls `_acquire_singleton_lock()` before constructing `CCMenuBarApp`. Lock file: `PID_FILE` = `APP_SUPPORT/menubar.pid`. On success: sets `FD_CLOEXEC` on the fd (required for clean `os.execv` restart), writes PID, returns open file handle (held on `run()`'s stack frame for the process lifetime). On failure: prints to stderr and calls `sys.exit(0)`. **Exit code 0 is mandatory**: launchd `KeepAlive=true` respawns on non-zero exit only.
