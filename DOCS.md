# ./ (project root)

## Role
Entry scripts of the project: the process entry that dispatches monitor modes and pane subprocesses, and the py2app build script that bundles and installs the menubar app. Touch to add a mode or change the bundle contents; all logic lives in `src/`.

## Public Interface
No `__init__.py`. Entry paths: `python3 workflow.py --mode <mode>` and `./venv/bin/python setup_py2app.py py2app`.

## Flow
`workflow.py` parses the mode and dispatches to the launcher, a pane package or the core monitor. `setup_py2app.py` builds the menubar bundle, prunes `src/` inside it, signs it, installs it and bootstraps its launch agent.

## Modules

### workflow.py (51 LOC)

**Purpose:** Single process entry point that parses the mode and dispatches to the launcher, a pane package, or the core monitor.
**Reads:** `sys.argv` via `src/startup.py`.
**Writes:** nothing directly.
**Called by:** invoked directly (main session start); pane commands generated by `src/tmux_launcher.py`.
**Calls out:** none.

---

### setup_py2app.py (141 LOC)

**Purpose:** Builds the menubar app bundle with py2app, prunes it, code-signs it, installs it into the user's Applications folder and bootstraps its launch agent.
**Reads:** `src/menubar/` sources and the launch-agent plist template; the code-signing identities of the keychain.
**Writes:** `dist/` and `build/`; `~/Applications/monitor-cc-menubar.app`; a launch-agent plist under `~/Library/LaunchAgents`; launchd state.
**Called by:** none; run manually with the `py2app` argument. Importing it starts the build, so tests extract its functions via AST.
**Calls out:** `setuptools`, `py2app`.

---

## State
None. `setup_py2app.py` replaces the installed bundle and launch agent on every run.
